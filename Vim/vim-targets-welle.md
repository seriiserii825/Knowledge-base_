# targets.vim — компактная шпаргалка

Плагин: `wellle/targets.vim`. Расширяет текстовые объекты `i`/`a`.

## Схема мнемоник

```
i / a   = inside / around      (что оставить: внутренность / вместе с границами)
n / l   = next / last          (следующий / предыдущий объект по строке)
q       = любая кавычка (' " `)
b       = любые скобки (() [] {})
```

Порядок ввода всегда: **`[count] c/d/y + i/a + [n/l] + символ`**
Например: `cin"` = change → inside → next → `"`.

---

## 1. Обычный объект под курсором (курсор ВНУТРИ него)

| Команда | Действие |
|---|---|
| `ci(` `ci)` `ci[` `ci{` `ci<` `cit` | внутри скобок / тега |
| `ca(` ... | вместе со скобками |
| `ci'` `ci"` `` ci` `` | внутри кавычек |
| `ci,` (и `. ; : + - = / \|  &`) | текущий элемент-разделитель |
| `cia` | текущий аргумент функции |

Если курсор **не внутри**, а рядом (например на запятой между кавычками) — плагин сам ищет ближайшую пару на строке (это и есть **seek**, работает без `n`/`l`).

---

## 2. Следующий / предыдущий объект (курсор где угодно)

Добавляем `n` (next) или `l` (last) между `i`/`a` и символом:

| Команда | Действие |
|---|---|
| `cin(` `cin"` `cin,` `cina` | следующие `()` / `""` / элемент / аргумент |
| `cil(` `cil"` `cil,` `cila` | предыдущие |
| `c2in"` | пропустить 1 пару кавычек, взять 2-ю следующую |

Пример:
```
<section class="foo" id="bar">
              ^курсор
```
`cin"` — прыгнет к `id="bar"` (следующая пара кавычек).

---

## 3. Любая кавычка / любая скобка

`iq`/`aq` и `ib`/`ab` — не привязаны к конкретному символу, берут ближайшую пару любого типа.

⚠️ **Число перед `iq`/`ib` — это НЕ "вперёд на N пар"**, а уровень вложенности вверх:
```
join("hello", "world")
      ^курсор внутри '"hello"'
```
`d2iq` — выйти на уровень выше и удалить внешние кавычки (если бы были вложенные).
Для перехода к следующей паре по строке используй `n`/`l` с конкретным символом: `in"`, не `iq`.

---

## Частые команды

```vim
ci(   ciq   cib
cin(  cin"  cina
cil(  cil"
c2ina
ci,   cin,
```

---

## Известный конфликт (Neovim 0.12+)

Начиная с Neovim 0.11–0.12, встроены дефолтные маппинги `in`/`an` (visual/operator-pending) —
"Select child/parent node" через LSP `selectionRange`. Они **перехватывают** ввод раньше, чем
targets.vim успевает увидеть третий символ (`in"`, `in(` и т.д.), из-за чего `cin"` ломается
с ошибкой `vim.lsp: method "textDocument/selectionRange" is not supported`.

Фикс (уже применён в `keys/map-nvim.vim`):
```vim
silent! xunmap in
silent! ounmap in
silent! xunmap an
silent! ounmap an
```

Проверка: `:verbose omap in"` — должна остаться только одна запись, от `targets.vim/plugin/targets.vim`.
