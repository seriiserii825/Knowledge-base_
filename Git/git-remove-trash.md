# Git remove trash — почему .git весит много и как почистить

## Диагностика

```bash
du -sh .git/* | sort -h          // что занимает место внутри .git (обычно objects/)
git count-objects -vH            // loose objects, packs, prune-packable
```

- `count` / `size` — loose objects (отдельные несжатые файлы)
- `packs` — сколько pack-файлов (в идеале 1)
- `size-pack` — размер упакованной истории
- `prune-packable` — loose objects, которые уже дублируются в pack (чистый мусор)

### Самые большие файлы в истории

```bash
git rev-list --objects --all \
  | git cat-file --batch-check='%(objecttype) %(objectname) %(objectsize) %(objectsize:disk) %(rest)' \
  | awk '$1=="blob"' | sort -k3 -n -r | head -30 \
  | awk '{printf "%8.1fK %8.1fK %s\n",$3/1024,$4/1024,$5}'
```

Колонки: размер файла, размер на диске (сжатый), путь.

### Какие коммиты добавили тяжёлые файлы

```bash
git log --oneline --stat -- assets/fonts
```

## git gc — сборка мусора

```bash
git gc                  // безопасно: упаковывает, удаляет мусор старше 2 недель
git gc --prune=now      // то же, но недостижимые объекты удаляются сразу
```

Что делает:
1. Пакует loose objects и много pack-файлов в один pack с дельта-сжатием
2. Удаляет недостижимые объекты (остатки rebase / amend / reset / удалённых веток),
   на которые не ссылаются ветки, теги, stash, reflog
3. Пакует refs в `packed-refs`, чистит старые записи reflog (90 дней, недостижимые — 30)

Коммиты, ветки и рабочие файлы не трогает. Историю не переписывает, force push не нужен.

`--prune=now` — без страховки в 2 недели. Пропадёт только то, на что ничего не ссылается
(например, коммит, потерянный после `reset --hard` и уже не в reflog). Если `git status`
чистый и всё запушено — терять нечего.

## Нормальный размер репо

- GitHub/GitLab рекомендуют < 1 GB, предупреждение на отдельный файл > 50 MB
- Десятки MB — норма, на скорость `status` / `log` / `diff` не влияет
- Проблемы начинаются с сотен MB: `node_modules`, `dist`, дампы БД, видео, PSD в истории

Не коммитить тяжёлые бинарники (исходные `.otf`, zip, исходники картинок) —
сразу финальные `woff2` / оптимизированные файлы. Однажды закоммиченное остаётся в истории навсегда.

## Вырезать файлы из истории (переписывает историю!)

```bash
yay -S git-filter-repo
git filter-repo --path assets/fonts/Barlow-Thin.ttf.zip --invert-paths   // удалить файл из всей истории
git filter-repo --strip-blobs-bigger-than 1M                             // удалить все блобы > 1 MB
git push --force
```

Меняет хеши всех коммитов после изменённого. Нужен force push, всем остальным —
переклонировать репо. Делать только если выигрыш реально большой (сотни MB).

## Пример: ag-casagratis (2026-10-30)

- `.git` = 147 MB, из них живой истории ~43 MB
- ~100 MB — 12 pack-файлов + 51 MB loose objects (1369 дублей) → лечится `git gc --prune=now`
- ~42 MB из живой истории — шрифты: исходные `.otf` + первая раздутая конвертация в woff/woff2
  (~1.5 MB каждый); в HEAD шрифты всего 2 MB
- Решение: только `git gc`, историю не переписывать
