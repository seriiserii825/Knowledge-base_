# GEO — Generative Engine Optimization

## 1. Что такое GEO?

**GEO (Generative Engine Optimization)** — это оптимизация сайта для повышения вероятности того, что его информация будет использоваться и цитироваться системами искусственного интеллекта:

- ChatGPT
- Google AI Overviews / AI Mode
- Gemini
- Perplexity
- Microsoft Copilot

GEO помогает сделать сайт понятным, доступным и полезным для AI-поиска.

**Важно:** GEO не заменяет традиционное SEO, а дополняет его.

---

## 2. GEO vs SEO

### SEO (Search Engine Optimization)

Цель — попасть на высокие позиции в поисковой выдаче Google или Bing.

**Пример запроса:**

`installazione pannelli solari Brescia`

Пользователь получает список сайтов и самостоятельно выбирает компанию.

### GEO (Generative Engine Optimization)

Цель — повысить вероятность того, что ИИ использует сайт как источник или порекомендует компанию.

**Пример запроса:**

`Quali aziende installano pannelli solari a Brescia? Confronta servizi, prezzi e affidabilità.`

ИИ может:

1. Найти несколько подходящих компаний.
2. Проанализировать доступную информацию.
3. Сравнить услуги и характеристики.
4. Сформировать ответ.
5. Привести ссылки на источники.

### Главное отличие

| SEO                 | GEO                                         |
| ------------------- | ------------------------------------------- |
| Позиции в поиске    | Присутствие в AI-ответах                    |
| Органический трафик | AI-упоминания, цитирования и трафик         |
| Ключевые слова      | Вопросы, сущности и пользовательские задачи |
| Title и Description | Чёткие ответы и фактическая информация      |
| Ссылочный профиль   | Авторитет и подтверждаемые источники        |
| Search Console      | Search Console + AI-мониторинг              |

SEO и GEO имеют общую основу: качественный контент, техническая доступность и доверие.

---

## 3. Как работает GEO

Упрощённая схема AI-поиска:

1. Пользователь задаёт вопрос.
2. AI-система определяет, нужна ли внешняя информация.
3. При необходимости выполняет поиск источников.
4. Получает доступный контент.
5. Анализирует информацию.
6. Формирует ответ.
7. Может добавить ссылки на источники.

Не все AI-ответы используют поиск в интернете. Поэтому корректная оптимизация не гарантирует попадание в конкретный ответ.

### Три основы GEO

**1. Доступность**

Поисковые роботы должны иметь возможность находить и читать страницы.

**2. Содержание**

Сайт должен предоставлять полезные ответы, факты, характеристики, услуги, цены и другую проверяемую информацию.

**3. Доверие**

Информация о компании должна быть достоверной, актуальной и согласованной с внешними источниками.

## 4. Что нужно сделать на WordPress

### 4.1. Доступность для AI-ботов

Проверить:

- robots.txt
- noindex
- HTTP-статусы
- Canonical URL
- XML Sitemap
- Cloudflare / WAF
- Доступность HTML
- Блокировки поисковых роботов
- Серверные ошибки
- Редиректы

Особое внимание уделить OAI-SearchBot.

### Пример robots.txt

```txt
User-agent: OAI-SearchBot
Allow: /

User-agent: GPTBot
Disallow: /
```

**Разница:**

- `OAI-SearchBot` — поисковый робот ChatGPT.
- `GPTBot` — робот, связанный со сбором информации для потенциального обучения моделей.

Можно разрешить поисковую доступность и отдельно ограничить использование контента для обучения.

Важно сохранить существующие правила безопасности, закрытые разделы и ограничения для других роботов.

---

### 4.2. Structured Data (JSON-LD)

Добавить корректные структурированные данные Schema.org.

Основные типы:

| Тип               | Назначение                  |
| ----------------- | --------------------------- |
| Organization      | Информация о компании       |
| LocalBusiness     | Локальная компания          |
| Service           | Услуга                      |
| Product           | Товар                       |
| Offer             | Цена и предложение          |
| Article           | Статья                      |
| BlogPosting       | Запись блога                |
| BreadcrumbList    | Хлебные крошки              |
| FAQPage           | Страница вопросов и ответов |
| Person            | Автор или специалист        |
| RealEstateListing | Объявление недвижимости     |

Использовать только те типы, которые соответствуют реальному содержанию страницы.

### Пример Organization

```json
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Example Company",
  "url": "https://example.com",
  "logo": "https://example.com/logo.png",
  "contactPoint": {
    "@type": "ContactPoint",
    "contactType": "customer service",
    "email": "info@example.com"
  }
}
```

### Автоматизация WordPress

Данные можно получать из:

- WordPress Settings
- ACF
- Custom Post Types
- Таксономий
- WooCommerce
- SEO-плагинов

**Важно:** не создавать дубли JSON-LD, если Yoast SEO, Rank Math или другой плагин уже генерирует соответствующую разметку.

JSON-LD помогает системам понимать содержимое, но не гарантирует цитирование сайта в AI-ответах.

### 4.3. Контент для AI-поиска

Основные рекомендации:

- Понятная структура H1–H6.
- Чёткое описание услуг.
- Ответы на реальные вопросы клиентов.
- Конкретные характеристики товаров.
- Актуальные цены, если доступны.
- Условия предоставления услуг.
- Географическая информация.
- Кейсы и реальные примеры.
- Информация об авторах и специалистах.
- Дата публикации и обновления.
- Внутренняя перелинковка.
- Уникальная, полезная информация.

### Пример страницы услуги

Плохая структура:

```txt
H1: Наши услуги

Мы предлагаем профессиональные
решения высокого качества.
```

Хорошая структура:

```txt
H1: Установка солнечных панелей в Брешии

H2: Какие услуги мы предоставляем?
H2: Какие панели устанавливаем?
H2: Сколько стоит установка?
H2: Сколько времени занимает монтаж?
H2: В каких городах работаем?
H2: Какие гарантии предоставляем?
H2: Часто задаваемые вопросы
H2: Контакты
```

Содержание должно отвечать на вопросы пользователей, а не просто повторять ключевые слова.

## 5. llms.txt

`llms.txt` — предлагаемый формат текстового файла с краткой картой информации сайта для AI-систем.

Располагается по адресу:

`https://example.com/llms.txt`

### Пример

```txt
# Example Company

> Company providing industrial services in Italy.

## Services

- [Consulting](https://example.com/consulting/)
- [Installation](https://example.com/installation/)

## Company

- [About us](https://example.com/about/)
- [Contacts](https://example.com/contacts/)
```

### Важно

- llms.txt не является обязательным стандартом GEO.
- Google не использует llms.txt для своих поисковых AI-функций.
- Наличие файла не гарантирует цитирование.
- Можно внедрять экспериментально.
- Не стоит делать его главным приоритетом.

Для 300+ WordPress-сайтов генерацию llms.txt можно добавить в плагин как дополнительную опцию.

## 7. Функциональность WordPress GEO Plugin

### 7.1. Technical Audit

Автоматические проверки:

- robots.txt
- noindex
- canonical
- sitemap.xml
- HTTP Status
- Redirects
- Broken Links
- HTML Content
- Meta Title
- Meta Description
- H1
- JSON-LD
- Open Graph
- Internal Links

### 7.2. AI Crawler Check

Проверять доступность для:

- OAI-SearchBot
- GPTBot
- Googlebot
- Bingbot
- Других релевантных AI-роботов

Нужно учитывать разницу между роботами поиска и роботами, собирающими данные для обучения.

Проверка robots.txt не заменяет реальный HTTP-запрос: WAF или CDN могут отдельно блокировать роботов.

### 7.3. Schema Manager

Функциональность:

- Определять существующую Schema.
- Проверять корректность JSON-LD.
- Находить отсутствующие обязательные поля.
- Выявлять дублирование.
- Интегрироваться с ACF.
- Создавать недостающие данные.

### 7.4. Content Audit

Проверять:

- Наличие H1.
- Структуру заголовков.
- Описание основной темы.
- Наличие полезных ответов.
- Дубли контента.
- Пустые страницы.
- Устаревшую информацию.
- Внутренние ссылки.

AI может формировать рекомендации по улучшению страниц.

Однако автоматическая оценка текста не является доказательством того, что страница будет цитироваться.

### 7.5. llms.txt Generator

Опциональная функция:

- Получение названия сайта.
- Краткое описание.
- Основные страницы.
- Основные услуги.
- Ссылка на контакты.
- Генерация файла llms.txt.

### 7.6. Remote API

Пример endpoint:

```txt
GET /wp-json/geo/v1/status
```

Пример ответа:

```json
{
  "site": "https://example.com",
  "wordpress_version": "6.x",
  "plugin_version": "1.0.0",
  "checks": {
    "robots": true,
    "sitemap": true,
    "schema": true,
    "noindex": false,
    "canonical": true
  }
}
```

Здесь `noindex: false` означает, например, что директива noindex не обнаружена. В реальной API-схеме лучше использовать однозначные поля вроде `has_noindex`.

### Безопасность API

Для каждого сайта:

- Уникальные учётные данные.
- HTTPS.
- Проверка авторизации.
- Минимальные разрешения.
- Ограничение частоты запросов.
- Логирование операций.
- Безопасное хранение секретов.
- Возможность отозвать доступ.

Не создавать публичные endpoints для изменения настроек без авторизации.

## 9. Как измерять эффективность GEO

Недостаточно установить Schema и считать, что сайт оптимизирован.

Нужно отдельно измерять техническое состояние и реальную видимость в AI-поиске.

### 9.1. Google Search Console

Использовать для:

- Индексации.
- Ошибок страниц.
- Поисковых запросов.
- Показов.
- Кликов.
- Динамики органического поиска.

Не все AI-показы и цитирования выделяются в отдельные отчёты.

### 9.2. Bing Webmaster Tools

Использовать AI Performance, когда отчёт доступен.

Показатели могут включать:

- Цитирования страниц.
- Страницы, использованные как источники.
- Запросы, связанные с AI-ответами.
- Динамику цитирований.

### 9.3. Web Analytics

Отслеживать реферальный трафик из:

- ChatGPT.
- Perplexity.
- Copilot.
- Других AI-сервисов.

Не каждый AI-переход передаёт корректный referrer.

### 9.4. AI Visibility Monitoring

Создать набор вопросов для каждой компании.

Например:

```txt
1. Best solar panel installers in Brescia
2. Solar panel installation companies in Lombardy
3. How much does solar panel installation cost?
4. Compare solar panel installation companies
```

Периодически проверять:

- Упоминается ли компания.
- Есть ли ссылка на сайт.
- Какие конкуренты упоминаются.
- Какие страницы цитируются.
- Насколько корректна представленная информация.

Результаты зависят от формулировки вопроса, модели, региона и времени.

Не считать единичный ответ ИИ стабильной позицией.

## 14. Главные ошибки GEO

**Ошибка 1.** Считать GEO заменой SEO.

**Ошибка 2.** Думать, что один llms.txt решит задачу.

**Ошибка 3.** Генерировать большое количество бесполезного AI-контента.

## 16. Итоговая стратегия

Для сети из 300+ WordPress-сайтов оптимальная стратегия:

1. Создать собственный WordPress GEO Plugin.
2. Автоматизировать технический аудит.
3. Использовать существующие SEO-плагины без дублирования.
4. Разработать централизованный GEO Manager.
5. Добавить безопасное подключение сайтов.
6. Использовать Go для массовых проверок.
7. Хранить историю результатов в PostgreSQL.
8. Создать Dashboard на Vue 3.
9. Улучшать контент на основе реальных задач пользователей.
10. Отдельно измерять AI-видимость и трафик.
11. Внедрять изменения постепенно.
12. Предлагать GEO как дополнительную услугу клиентам.

**Главная идея:** не устанавливать случайные GEO-инструменты на каждый сайт, а создать собственную масштабируемую систему технического аудита, оптимизации и мониторинга.

GEO — это не один файл, один плагин или одна настройка. Это сочетание технического SEO, качественного контента, структурированных данных, авторитетности и измерения присутствия в AI-поиске.
