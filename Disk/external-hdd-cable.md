## Как скопировать Samsung → HGST 1 ТБ (Arch, ddrescue)

**Почему ddrescue, а не rsync** (данных ~600 ГБ): по времени примерно одинаково (~3 ч: ddrescue читает весь 1 ТБ, но подряд; rsync — только файлы, но головки прыгают). Выбор — из-за умирающего диска:

| | rsync | ddrescue |
|---|---|---|
| Плохое место | долбит его повторами, добивает головки | пропускает, вернётся в конце |
| Головки | прыгают по диску | читают подряд, бережно |
| Диск отвалился | неясно, что скопировалось, файл на середине битый | `rescue.map` помнит всё, продолжит с места |
| Битая файловая система | может не смонтироваться | копирует сектора, ФС не важна |

**Зачем tmux** — не для скорости: держит копирование живым, если закроется терминал, упадёт i3 или отвалится SSH. Без него закрытое окно = оборванное копирование.

Полная посекторная копия. У Samsung и HGST HTS721010A9E630 одинаковое число секторов (1 953 525 168) → копия 1:1. Всё на HGST будет стёрто.

**Подготовка**

```bash
sudo pacman -S ddrescue tmux
tmux new -s rescue          # вернуться: tmux attach -t rescue
```

- Samsung — в **ORICO**, HGST — в **Tracer** (кабель USB-C → A **3.0**, не белый USB 2.0).
- Оба — **напрямую в USB 3.0 сзади**, без хаба. Samsung не трогать во время копирования.
- Если ПК настольный — Samsung лучше **напрямую по SATA внутрь**.
- Ничего не записывать на Samsung, не запускать на нём fsck/chkdsk.

**1. Найти диски — ⚠️ перепутать = стереть Samsung**

```bash
lsblk -o NAME,SIZE,MODEL,MOUNTPOINT
sudo smartctl -i -d sat /dev/sdX | grep Model   # если ORICO показывает свою модель вместо диска
```

Если что-то смонтировано — `sudo umount /dev/sdX1`. Ниже `sdS` = Samsung, `sdH` = HGST.

**2. Копирование**

```bash
# Проход 1: быстро всё здоровое, плохие места пропускает
sudo ddrescue -f -n /dev/sdS /dev/sdH ~/rescue.map

# Проход 2: дочитать плохие места, до 3 попыток
sudo ddrescue -f -d -r3 /dev/sdS /dev/sdH ~/rescue.map
```

- `~/rescue.map` — что уже скопировано (на системном диске). ~3 ч, если диск в порядке.

**3. Если Samsung отвалился** — переподключить, **заново `lsblk` (буква могла смениться!)**, запустить ту же команду с тем же `~/rescue.map` — продолжит с места остановки.

**4. После**

```bash
ddrescuelog -t ~/rescue.map                  # сколько % спасено
sudo partprobe /dev/sdH
lsblk -f /dev/sdH                            # должен появиться NTFS
sudo mount -t ntfs3 -o ro /dev/sdH1 /mnt && ls /mnt   # если "dirty" → -o ro,force
```

- Проверить, что важные файлы открываются → **Samsung больше не включать**.
- HGST станет полной копией (тот же UUID) — не подключать оба одновременно. Запись HGST в `mnt` (`zsh_mount`) перестанет работать.

## Железо

- **ORICO** (Micro-B 3.0, чип JMS578, видится как «TOSHIBA External USB 3.0») — исправен.
- **Tracer** (USB-C) — исправен, но с белым кабелем только USB 2.0; на USB 2.0 HDD 7200 отваливается при раскрутке.
- **Хаб Hama USB 3.0** — без блока питания только для SSD/флешек/одного HDD. Блок: **строго 5V**, 2–3 A, штекер скорее всего 3.5×1.35 мм (сверить надпись у гнезда).
- Перед отключением диска — всегда `umnt`.
