# Neovim (vim-plug): установка и обновление плагинов

Плагины перечислены в `~/.config/nvim/plugins.vim` (`Plug '...'`), ставятся в `~/.config/nvim/autoload/plugged/`.

## Команды vim-plug

| Команда | Что делает |
|---|---|
| `:PlugInstall` | ставит только **недостающие** плагины (есть в `plugins.vim`, но ещё не скачаны). Уже установленные **не обновляет** |
| `:PlugUpdate` | обновляет **все** установленные плагины до последней версии (и ставит недостающие) |
| `:PlugUpdate vim-floaterm` | обновляет **только** указанный плагин |
| `:PlugUpgrade` | обновляет сам vim-plug, не плагины |
| `:PlugDiff` | показать, что изменилось после последнего обновления |
| `:PlugSnapshot <файл>` | сохранить снимок текущих версий всех плагинов |

## Что происходит при :PlugUpdate

1. Открывается окно, vim-plug параллельно скачивает обновления **всех** плагинов.
2. У плагинов с командой установки (`do`) она запускается заново. Например, у `markdown-preview.nvim` — `cd app && npx --yes yarn install` (ставит `node_modules`).
3. В конце в окне список: что обновилось, что уже было последним, где ошибка.
4. Изменения действуют после перезапуска Neovim.

## Что может пойти не так

- **Изменилось поведение или настройки** — плагин переименовал команду или опцию, и конфиг в `modules/*.vim` выдаёт ошибку при старте или что-то перестаёт работать.
- **Плагин требует что-то новое** — более новую версию Neovim, Node или внешнюю программу.
- **Плагин заброшен или переехал** — по нему будет ошибка, остальные обновятся.

## Как обновлять безопасно

1. Сохранить снимок текущих версий:
   ```vim
   :PlugSnapshot ~/plug-snapshot-before.vim
   ```
2. Обновить:
   ```vim
   :PlugUpdate
   ```
3. Посмотреть, что поменялось:
   ```vim
   :PlugDiff
   ```
   Если какой-то плагин сломался — курсор на него, нажать `X`: он откатится к прежней версии.
4. Если сломалось много и непонятно что — откатить всё разом и перезапустить Neovim:
   ```vim
   :source ~/plug-snapshot-before.vim
   ```

С таким снимком обновлять всё сразу нормально: в худшем случае откат за минуту.

## Какие плагины можно обновить

В vim-plug нет команды «показать доступные обновления»: `:PlugStatus` показывает только установлен/не хватает, `:PlugDiff` — новые коммиты уже **после** `:PlugUpdate`.

Из терминала — список плагинов с новыми коммитами, **ничего не обновляя** (только `git fetch`):

```bash
cd ~/.config/nvim/autoload/plugged && for d in */; do d=${d%/}; [ -d "$d/.git" ] || continue; git -C "$d" fetch -q 2>/dev/null; n=$(git -C "$d" rev-list --count HEAD..@{u} 2>/dev/null); [ "${n:-0}" -gt 0 ] && echo "$d: $n new commit(s)"; done
```

Пустой вывод — всё последнее. Обновить только найденные: `:PlugUpdate имя1 имя2`.

## Одинаковые версии плагинов на всех компьютерах

Плагины **не** хранятся в git: в `.gitignore` репозитория nvim (`~/Documents/Apps/nvim`) стоит `autoload/` — туда входят и `autoload/plugged`, и сам `plug.vim`. Поэтому `git pull` на другом компьютере приносит только список плагинов (`plugins.vim`) и настройки, а версии плагинов там остаются старыми.

Чтобы версии были **в точности** одинаковыми, в репозитории лежит снимок `plug-snapshot.vim` (коммит каждого плагина).

**На компьютере, где обновлял:**

1. `:PlugUpdate` — обновить, проверить, что всё работает.
2. Перезаписать снимок:
   ```vim
   :PlugSnapshot! ~/.config/nvim/plug-snapshot.vim
   ```
   (`!` — перезаписать без вопроса.) Или из терминала:
   ```bash
   nvim --headless "+PlugSnapshot! $HOME/.config/nvim/plug-snapshot.vim" +qa
   ```
3. Закоммитить `plug-snapshot.vim` вместе с остальными изменениями конфига.

**На другом компьютере:**

1. `git pull` в `~/Documents/Apps/nvim`.
2. В Neovim:
   ```vim
   :source ~/.config/nvim/plug-snapshot.vim
   ```
   Снимок выставляет каждому плагину нужный коммит и запускает `PlugUpdate!` — ставит недостающие и переводит остальные ровно на эти версии.
3. Перезапустить Neovim.

## Проверка после обновления: :checkhealth

Отдельного режима «только ошибки» у `:checkhealth` нет.

**Внутри Neovim:** `:checkhealth` — в заголовке каждого раздела справа видно `✅`, `1 ⚠️` или `1 ❌`. Поиск `/ERROR` и `n` — от ошибки к ошибке.

**Из терминала — только ошибки и предупреждения с названием раздела:**

```bash
nvim --headless "+checkhealth" "+w! /tmp/health.txt" +qa
grep -n -E "^[a-zA-Z.]+: |ERROR|WARNING" /tmp/health.txt
```

Первая команда сохраняет весь отчёт в файл, вторая показывает заголовки разделов, ошибки и предупреждения.

Только проверка одного плагина: `:checkhealth kulala`.

## Случаи из практики

### markdown-preview: `<leader>mp` ничего не открывает

Причина: пустая `app/node_modules` у плагина, сервер превью падает с `Cannot find module 'tslib'`. Скорее всего, после обновления/переустановки не отработала команда установки.

Исправление (или `:call mkdp#util#install()` внутри Neovim):

```bash
cd ~/.config/nvim/autoload/plugged/markdown-preview.nvim/app && npx --yes yarn install
```

Проверить, что сервер стартует: `node index.js` в той же папке — без ошибки `Cannot find module`.

### :checkhealth — `E5009: Invalid $VIMRUNTIME` и `Unknown function: health#report_start`

```
E5009: Invalid $VIMRUNTIME: /usr/share/nvim/runtime
Lua: function health#floaterm#check[1]..., Vim(call):E117: Unknown function: health#report_start
```

- Причина — старый `vim-floaterm`: его `autoload/health/floaterm.vim` вызывает `health#report_start`, которую убрали в Neovim 0.12.
- `E5009` тут ложная тревога: `:checkhealth` выводит этот общий текст, когда падает проверка какого-то плагина. Runtime в порядке (проверить: `pacman -Qkk neovim` → `0 altered files`).
- Исправление: обновить плагин — `:PlugUpdate vim-floaterm` (в новой версии старого файла проверки нет), перезапустить Neovim.

### :checkhealth после `:PlugUpdate` всех плагинов (Neovim 0.12.6)

floaterm после обновления — ✅. Осталось:

**Ошибка — `kulala`: `kulala-core not found`**

- После обновления `kulala.nvim` стал версии 7.0.0, ему нужна отдельная программа `kulala-core`.
- По тексту ошибки плагин скачивает её сам при первом использовании: открыть `.http` файл, выполнить запрос, потом `:checkhealth kulala`.
- Если не скачается — задать путь опцией `kulala_core.path` в `setup` (`~/.config/nvim/modules/kulala.vim`).

**Предупреждения — не критичные**

| Раздел | Предупреждение | Что делать |
|---|---|---|
| `coc` | Node.js v18.19.0 < 22.15.0 | сейчас работает, но может сбоить; `nvm install 22 && nvm alias default 22` (поменяет Node для всего остального тоже) |
| `vim.provider` | нет npm-пакета `neovim` | нужен только для плагинов на JavaScript через провайдер; обычно игнорировать или `npm install -g neovim` |
| `which-key` | не установлен `mini.icons` | информационное: иконки берутся из `nvim-web-devicons`, он есть |
