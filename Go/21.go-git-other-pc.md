# 21. Git и другой ПК — клон, обновления, теги

Как держать `go-scripts` на нескольких ПК через git и что делать, когда вышла
новая версия go-libs или go-scripts. Сборка и перенос готового бинарника без
git — в 20.

## 1. Первая установка — git clone + go install

```
git clone git@github.com:seriiserii825/go-scripts.git
cd go-scripts
go install .
go install github.com/seriiserii825/go-libs/cmd/fzf-word-filter@latest
```

- `go mod tidy` **не нужен**: `go.mod` и `go.sum` закоммичены, `go install`
  сам скачает go-libs нужной версии.
- `go.work` в `.gitignore` → в клоне его нет → go-libs берётся **по тегу** из
  `go.mod`, а не из `../go-libs`.
- Бинарники — в `~/go/bin` (должен быть в `PATH`, см. 19).
- Обновить: `git pull && go install .`

## 2. Перед клоном — всё выпустить на исходном ПК

Иначе на другом ПК не соберётся: `go.mod` ссылается на тег, которого ещё нет.

```
# go-libs
git add . && git commit -m "..." && git push
git tag v0.9.0 && git push --tags

# go-scripts
GOWORK=off go get github.com/seriiserii825/go-libs@v0.9.0
GOWORK=off go mod tidy
git add go.mod go.sum && git commit -m "..." && git push
```

Если на другом ПК тег не находится или репо приватный:

```
GOPROXY=direct go install .                       # тег ещё не в proxy.golang.org
go env -w GOPRIVATE=github.com/seriiserii825/*    # навсегда для своих репо
```

Хочешь там же править go-libs — склонировать рядом в `../go-libs` и
`go work init . ../go-libs`.

## 3. Вышла новая версия go-libs

На другом ПК напрямую делать **ничего не нужно**: go-scripts берёт версию
go-libs из своего `go.mod`. Пока там старый тег — новый тег ни на что не
влияет.

1. На **исходном** ПК поднять версию в go-scripts и запушить:

   ```
   cd ~/Documents/go/go-scripts
   GOWORK=off go get github.com/seriiserii825/go-libs@v0.10.0
   GOWORK=off go mod tidy
   GOWORK=off go build ./...      # проверить, что собирается по тегу
   git add go.mod go.sum && git commit -m "..." && git push
   ```

   Те же три `GOWORK=off`-команды одним скриптом
   (`~/Documents/bash/bash-scripts/go-update-libs.sh`, он в `PATH`) — из папки
   проекта:

   ```
   go-update-libs.sh          # latest — самый большой тег go-libs
   go-update-libs.sh v0.9.0   # конкретный тег
   ```

   Внутри только `go get`, `go mod tidy`, `go build ./...` с `GOWORK=off`
   (`set -e` — стоп на первой ошибке). Тег и `git push` — вручную.

2. На **другом** ПК — обычное обновление, `go install` сам скачает новую
   go-libs:

   ```
   git pull && go install .
   ```

3. Если менялся `cmd/fzf-word-filter` — переустановить на **каждом** ПК, это
   отдельный бинарник, `go.mod` go-scripts его не обновляет:

   ```
   go install github.com/seriiserii825/go-libs/cmd/fzf-word-filter@v0.10.0
   ```

Не делать `go get …@latest` прямо в клоне на другом ПК: `go.mod` там
разойдётся с репо, при следующем `git pull` будет конфликт. Версию поднимать в
одном месте и пушить.

## 4. Изменил go-scripts и поставил тег

go-scripts — **программа**, а не библиотека: никто не подключает её по версии
через `go.mod`, тег просто отмечает коммит. На исходном ПК:

```
git add . && git commit -m "..." && git push
git tag v1.2.0 && git push --tags    # тег — по желанию
```

### Другой ПК с клоном — тег не важен

```
cd go-scripts
git pull && go install .
```

Собирается то, что сейчас в ветке — последний запушенный коммит, есть тег или
нет.

Нужна именно версия по тегу, а не последний коммит:

```
git fetch --tags
git checkout v1.2.0 && go install .
git checkout main           # вернуться, иначе git pull не обновит ветку
```

### Другой ПК без клона — go install @тег

`package main` у go-scripts лежит в корне модуля, поэтому его можно поставить
одной командой, как `fzf-word-filter`:

```
go install github.com/seriiserii825/go-scripts@latest   # самый большой тег
go install github.com/seriiserii825/go-scripts@v1.2.0   # конкретный
```

- Тут тег **важен**: `@latest` — самый большой тег, если тегов нет — последний
  коммит.
- `go.work` не используется, go-libs берётся по версии из `go.mod` go-scripts.
- Не сработает, если в `go.mod` есть `replace`.
- Тег должен быть запушен (`git push --tags`). Новый тег не находится —
  `GOPROXY=direct go install …@v1.2.0`.
- Обновить — эта же команда.

Если на другом ПК go-scripts только запускаешь и не правишь — проще без клона.

## 5. Изменил и go-libs, и go-scripts — порядок выпуска

Пример: в go-libs добавил пакет `tools`, а go-scripts уже его использует.
Порядок важен — **сначала go-libs**: пока нет тега, `GOWORK=off go build` в
go-scripts падает (`no required module provides package …/go-libs/tools`),
и на другом ПК не соберётся. С `go.work` локально всё работает — это и
обманчиво.

1. go-libs — коммит и тег (новый пакет/функция → minor, `v0.8.0` → `v0.9.0`):

   ```
   cd ~/Documents/go/go-libs
   go vet ./... && go test ./...
   git add . && git commit -m "feat: tools package" && git push
   git tag v0.9.0 && git push --tags
   ```

2. go-scripts — поднять go-libs, проверить **по тегу**, закоммитить:

   ```
   cd ~/Documents/go/go-scripts
   GOWORK=off go get github.com/seriiserii825/go-libs@v0.9.0
   GOWORK=off go mod tidy
   GOWORK=off go build ./... && go test ./...
   git add . && git commit -m "feat: ..." && git push
   ```

   Тег не находится — `GOPROXY=direct` перед `go get`.
   Или одной командой: `go-update-libs.sh v0.9.0` (см. §3), потом `go test ./...`
   и коммит.

3. go-scripts — тег (по желанию, нужен для `go install …@latest` без клона):

   ```
   git tag --sort=-v:refname | head -1   # последний тег
   git tag vX.Y.0 && git push --tags     # следующий
   go install .                          # обновить у себя
   ```

4. Другой ПК — `git pull && go install .` или
   `go install github.com/seriiserii825/go-scripts@latest` (см. §4).

Какую цифру поднимать (для обоих репо):

- patch `v0.9.1` — фикс без изменения API;
- minor `v0.10.0` — новая функция, пакет, команда;
- major `v1.0.0` → `v2.0.0` — ломающие изменения (для go-libs путь модуля
  меняется на `…/go-libs/v2`).

## 6. Шпаргалка — что делать на другом ПК

| Что изменилось | На исходном ПК | На другом ПК (клон) | На другом ПК (без клона) |
|---|---|---|---|
| go-scripts | commit, push (+ тег) | `git pull && go install .` | `go install …/go-scripts@latest` |
| go-libs | тег go-libs → `go get` в go-scripts → push | `git pull && go install .` | `go install …/go-scripts@latest` (нужен новый тег go-scripts) |
| `fzf-word-filter` | тег go-libs | `go install …/cmd/fzf-word-filter@<тег>` | то же |
