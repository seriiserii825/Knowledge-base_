# 20. go run / build / install / work и перенос на другой ПК

## 1. В чём разница

| Команда | Что делает | Где результат |
|---|---|---|
| `go run .` | собирает во временную папку, запускает, удаляет | нигде |
| `go build -o app .` | собирает бинарник | `./app` в текущей папке |
| `go install .` | собирает и кладёт бинарник | `~/go/bin/<имя>` |
| `go work` | **ничего не собирает** — настройка | файл `go.work` |

- `go run .` — для разработки: поправил → запустил.
- `go install .` — себе на этот ПК: бинарник доступен из любой папки
  (`~/go/bin` в `PATH`). Каждый раз **перезаписывает** старый. При ошибке
  компиляции старый остаётся.
- `go build` — чтобы получить файл и куда-то его отнести.
- Имя бинарника для `go install` — последняя часть пути модуля из `go.mod`:
  `module github.com/seriiserii825/go-scripts` → `go-scripts`.

## 2. go.work

`go.work` говорит Go: вместо версии библиотеки из `go.mod` бери **локальную
папку** (`../go-libs`). Влияет на `run`, `build`, `install`, `test`.

```
go work init . ../go-libs   # создать (go.work — в .gitignore)
GOWORK=off go build .       # временно выключить: собрать по тегу из go.mod
```

С `go.work` в бинарник попадут незакоммиченные правки библиотеки. Для
бинарника на другой ПК — всегда `GOWORK=off`.

## 3. Другой ПК — два способа

| Способ | Нужно на другом ПК | Когда |
|---|---|---|
| `git clone` + `go install` (п. 4) | Go, git, доступ к GitHub | свой ПК, будешь обновлять |
| готовый бинарник `go build` (п. 5–6) | ничего | нет Go / нет доступа к репо |

## 4. Другой ПК из исходников — git clone + go install

```
git clone git@github.com:seriiserii825/go-scripts.git
cd go-scripts
go install .
go install github.com/seriiserii825/go-libs/cmd/fzf-word-filter@latest
```

- `go mod tidy` **не нужен**: `go.mod` и `go.sum` закоммичены, `go install`
  сам скачает go-libs нужной версии.
- `go.work` в `.gitignore` → в клоне его нет → go-libs берётся **по тегу** из
  `go.mod`, а не из `../go-libs`.
- Бинарники — в `~/go/bin` (должен быть в `PATH`, см. 19).
- Обновить: `git pull && go install .`

Перед этим на **исходном** ПК всё должно быть выпущено, иначе не соберётся
(`go.mod` ссылается на тег, которого ещё нет):

```
# go-libs
git add . && git commit -m "..." && git push
git tag v0.9.0 && git push --tags

# go-scripts
GOWORK=off go get github.com/seriiserii825/go-libs@v0.9.0
GOWORK=off go mod tidy
git add go.mod go.sum && git commit -m "..." && git push
```

Если на другом ПК тег не находится или репо приватный:

```
GOPROXY=direct go install .                       # тег ещё не в proxy.golang.org
go env -w GOPRIVATE=github.com/seriiserii825/*    # навсегда для своих репо
```

Хочешь там же править go-libs — склонировать рядом в `../go-libs` и
`go work init . ../go-libs`.

## 5. Собрать бинарник для другого ПК

```
cd ~/Documents/go/go-scripts
GOWORK=off go build -o go-scripts .
GOWORK=off go build -o fzf-word-filter github.com/seriiserii825/go-libs/cmd/fzf-word-filter
```

- Go-бинарник **статический** (`file go-scripts` → `statically linked`): Go
  на другом ПК не нужен, библиотеки тоже.
- `fzf-word-filter` — второй бинарник, без него fzf ищет обычным способом
  (без `resdow` → `Restore from Downloads`).
- Оба ПК Arch x86_64 — собирать как есть. Для другой архитектуры/ОС:
  `GOOS=linux GOARCH=arm64 go build ...`.

## 6. Установить бинарник на другом ПК

Скопировать оба файла (`scp`, флешка) и положить в `~/.local/bin`:

```
mkdir -p ~/.local/bin
mv go-scripts fzf-word-filter ~/.local/bin/
chmod +x ~/.local/bin/go-scripts ~/.local/bin/fzf-word-filter
```

- `chmod +x` — если файлы шли через флешку/мессенджер, право на запуск могло
  потеряться.
- `~/.local/bin` должен быть в `PATH`:
  `echo $PATH | tr ':' '\n' | grep local`. Если нет — в `~/.zshrc`:
  `export PATH="$HOME/.local/bin:$PATH"`.
- Для всех пользователей: `sudo mv go-scripts fzf-word-filter /usr/local/bin/`.

Запуск — из любой папки: `go-scripts`, `go-scripts --help`.

## 7. Что ещё нужно на другом ПК

Бинарник вызывает внешние программы — без них конкретная команда выдаст
ошибку с командой установки:

| Программа | Установка | Нужна для |
|---|---|---|
| `fzf` | `sudo pacman -S fzf` | меню, cyr-to-lat, generate-password |
| `xclip` / `wl-copy` | `sudo pacman -S xclip` / `wl-clipboard` | буфер обмена |
| `notify-send` | `sudo pacman -S libnotify` | уведомления |
| `id3convert` | `sudo pacman -S id3lib` | cyr-to-lat (без него шаг пропускается) |
| `woff2_compress` | `sudo pacman -S woff2` | convert-fonts |
| `ttf2woff` | `npm install -g ttf2woff` | convert-fonts |

Для `create-project` — ещё шаблон `~/Documents/Sites/wp-projects/bs-vite`.

Проверка — через `tools.Require` из go-libs (пакет `tools`): `go-scripts` без
аргументов сразу проверит `fzf` и `fzf-word-filter`, каждая команда — свои
программы. Нет обязательной → ошибка со списком команд установки, нет
необязательной → только предупреждение.
