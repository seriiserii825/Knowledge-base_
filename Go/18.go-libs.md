# 18. go-libs — своя библиотека как Go-модуль

Общий код для скриптов вынесен в модуль `github.com/seriiserii825/go-libs`
(`~/Documents/go/go-libs`). Вместо git submodule (как было с `py-libs`) каждый
проект подключает нужную **версию** через git-тег.

## 1. Структура

Один модуль (`go.mod` в корне), внутри пакеты по папкам:

```
go-libs/
  go.mod          // module github.com/seriiserii825/go-libs
  color/color.go  // package color
  msg/msg.go      // package msg
```

- `main.go` не нужен — это библиотека, не `package main`.
- Импорт в проекте: `github.com/seriiserii825/go-libs/msg`.
- Экспортируется только то, что с заглавной буквы (`msg.Info`).
- Нельзя называть пакеты `select` (ключевое слово), лучше не называть `print`
  (встроенная функция).

## 2. Локальная разработка — go work

В проекте (например `go-scripts`):

```
go work init . ../go-libs
echo go.work >> .gitignore
echo go.work.sum >> .gitignore
```

Пока есть `go.work`, Go берёт **локальную папку** `../go-libs` — правки видны
сразу, теги и версия из `go.mod` игнорируются.

## 3. Выпуск новой версии — тег

В `go-libs`:

```
git add . && git commit -m "..."
git push
git tag v0.1.1
git push --tags
```

- `v0.1.1` (patch) — фикс без изменения API.
- `v0.2.0` (minor) — новые функции.
- Запушенный тег **не перемещать и не пересоздавать** — Go кэширует checksum
  (`sum.golang.org`), будет `checksum mismatch`. Ошибся — делай следующий тег.

## 4. Использование версии в проекте

```
GOWORK=off go get github.com/seriiserii825/go-libs@v0.1.1
GOWORK=off go mod tidy
GOWORK=off go run .
```

- В `go.mod` появится `require github.com/seriiserii825/go-libs v0.1.1` + файл
  `go.sum` — оба коммитить.
- `@latest` — самый большой тег.
- `GOWORK=off` — временно выключить `go.work`, чтобы проверить работу именно по
  тегу. Без `go.work` (другая машина) всегда используется версия из `go.mod`.

## 5. Если новый тег не находится

Модули качаются через `proxy.golang.org`, новый тег может появиться с задержкой.

```
GOPROXY=direct GOWORK=off go get github.com/seriiserii825/go-libs@v0.1.1
```

Навсегда для своих репо (обязательно, если репо приватный):

```
go env -w GOPRIVATE=github.com/seriiserii825/*
```

## 6. Цикл работы

1. Правишь `go-libs`, проверяешь в проекте с `go.work`.
2. Коммит → push → новый тег.
3. В каждом проекте: `go get github.com/seriiserii825/go-libs@vX.Y.Z` → коммит
   `go.mod` и `go.sum`.
