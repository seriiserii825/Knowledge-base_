# Go Modules — Модули в Go

## 1. Что такое Go Module?

**Go Module** — это набор Go-пакетов, объединённых в один проект и управляемых через файл `go.mod`.

Модуль нужен для:

1. Определения имени и пути проекта.
2. Управления внешними зависимостями и их версиями.
3. Организации нескольких пакетов внутри одного проекта.
4. Импорта собственных пакетов из других директорий.

### Сравнение с JavaScript

| Go            | JavaScript / Node.js                                    |
| ------------- | ------------------------------------------------------- |
| `go.mod`      | `package.json`                                          |
| `go.sum`      | `package-lock.json` (похожая роль, но не полный аналог) |
| `go mod init` | `npm init`                                              |
| `go get`      | `npm install` (для зависимостей проекта)                |
| `go mod tidy` | Нет точного аналога                                     |
| `go run .`    | `node index.js`                                         |

Go Module похож на Node.js-проект с собственным `package.json`.

## 2. Создание Go-модуля

Перейдём в директорию проекта:

```bash
mkdir go-course
cd go-course
```

Инициализируем модуль:

```bash
go mod init github.com/seriiserii825/go-course
```

Команда создаст файл `go.mod`:

```go
module github.com/seriiserii825/go-course

go 1.25.0
```

Здесь:

- `module` — уникальный путь модуля.
- `github.com/seriiserii825/go-course` — путь для импорта пакетов.
- `go 1.25.0` — минимальная версия Go, объявленная модулем (фактическое значение зависит от установленной версии).

**Важно:** наличие GitHub в имени модуля не означает, что Go автоматически создаёт репозиторий или загружает туда код.

## 3. Один модуль — много папок

Один `go.mod` может использоваться для всего проекта.

Пример структуры учебного курса:

```text
go-course/
├── go.mod
├── go.sum
├── 01-go-install/
│   └── about-me/
│       └── main.go
├── 02-variables/
│   └── main.go
├── 03-functions/
│   └── main.go
└── 04-files/
    └── main.go
```

`go.sum` появляется при необходимости, например при добавлении внешних зависимостей.

Все эти директории принадлежат **одному Go-модулю**.

Создавать `go.mod` внутри каждой папки не нужно.

Например:

```bash
mkdir 02-variables
cd 02-variables
```

Создаём `main.go`:

```go
package main

import "fmt"

func main() {
    name := "Sergey"
    fmt.Println(name)
}
```

Запускаем:

```bash
go run .
```

Go автоматически ищет `go.mod` в текущей директории и её родительских директориях.

Можно также запустить программу из корня проекта:

```bash
go run ./02-variables
```

## 4. Отличие Module от Package

**Module** — проект или библиотека, содержащие один или несколько пакетов.

**Package** — набор Go-файлов в одной директории, объединённых общим именем пакета.

Пример:

```text
go-course/
├── go.mod
├── main.go
└── utils/
    └── greeting.go
```

В `go.mod`:

```go
module github.com/seriiserii825/go-course

go 1.25.0
```

В `utils/greeting.go`:

```go
package utils

func SayHello() string {
    return "Hello from utils!"
}
```

В `main.go`:

```go
package main

import (
    "fmt"

    "github.com/seriiserii825/go-course/utils"
)

func main() {
    fmt.Println(utils.SayHello())
}
```

Запуск:

```bash
go run .
```

Результат:

```text
Hello from utils!
```

Обрати внимание:

- `utils` — имя пакета.
- `github.com/seriiserii825/go-course/utils` — путь импорта.
- `SayHello` начинается с заглавной буквы, поэтому функция доступна другим пакетам.
- Функции с маленькой буквы доступны только внутри своего пакета.

## 5. Установка внешних зависимостей

Допустим, проекту нужна библиотека для генерации UUID:

```bash
go get github.com/google/uuid
```

Go добавит зависимость в `go.mod`:

```go
module github.com/seriiserii825/go-course

go 1.25.0

require github.com/google/uuid v1.6.0
```

Версия приведена для примера. Фактически будет выбрана версия, разрешённая командой.

Теперь библиотеку можно использовать:

```go
package main

import (
    "fmt"

    "github.com/google/uuid"
)

func main() {
    id := uuid.New()
    fmt.Println(id)
}
```

В отличие от `node_modules`, зависимости Go обычно хранятся в общем кэше модулей.

Посмотреть путь к кэшу:

```bash
go env GOMODCACHE
```

## 6. Основные команды Go Modules

### Инициализация

```bash
go mod init github.com/username/project
```

Создаёт новый `go.mod`.

### Добавление зависимости

```bash
go get github.com/google/uuid
```

Добавляет или обновляет зависимость проекта.

### Очистка зависимостей

```bash
go mod tidy
```

- Добавляет недостающие зависимости.
- Удаляет неиспользуемые зависимости из `go.mod`.
- Обновляет `go.sum` при необходимости.

### Просмотр зависимостей

```bash
go list -m all
```

### Проверка зависимостей

```bash
go mod verify
```

Проверяет, что скачанные модули в кэше не изменились относительно ожидаемых данных.

### Просмотр текущего модуля

```bash
go env GOMOD
```

Выводит путь к используемому файлу `go.mod`.

## 7. Один модуль или несколько?

### Вариант A — один модуль (рекомендуется для курса)

```text
go-course/
├── go.mod
├── 01-basics/
│   └── main.go
├── 02-variables/
│   └── main.go
└── 03-functions/
    └── main.go
```

Преимущества:

- Один файл `go.mod`.
- Общие зависимости.
- Простое управление.
- Удобно для учебных проектов.

### Вариант B — отдельный модуль для каждого проекта

```text
projects/
├── file-manager/
│   ├── go.mod
│   └── main.go
└── rest-api/
    ├── go.mod
    └── main.go
```

Каждый проект имеет собственные зависимости, версии и путь модуля.

Такой подход подходит для самостоятельных приложений.

Важно: вложенная директория с собственным `go.mod` считается отдельным модулем.

## 8. Правила для моего Go-курса

Репозиторий:

`github.com/seriiserii825/go-course`

Правила:

1. Один `go.mod` в корне репозитория.
2. Каждый урок находится в отдельной директории.
3. В каждом уроке можно создать собственный `main.go`.
4. Все примеры могут использовать общие зависимости.
5. Для нового урока не требуется повторять `go mod init`.
6. Для отдельных крупных приложений можно создавать самостоятельные модули.

### Пример команд

```bash
# Создать модуль один раз
cd ~/Documents/go-course
go mod init github.com/seriiserii825/go-course

# Создать следующий урок
mkdir 02-variables
cd 02-variables

# Создать исходный файл
touch main.go

# Запустить программу
go run .

# Скомпилировать программу
go build -o variables .
```

**Итог:** Go Module — это уровень управления проектом и зависимостями. Один модуль может содержать множество директорий и пакетов. Для учебного репозитория достаточно одного `go.mod` в корне.
