# 17. Interface в Go

`interface` — набор методов, которые должен реализовать тип. Если тип реализует все методы интерфейса, он автоматически считается его реализацией — явного `implements` не требуется.

## 1. Зачем нужен interface

Интерфейс описывает **поведение**, а не структуру данных. Это позволяет писать функции, которые работают с разными типами, если те реализуют нужные методы.

```go
type Speaker interface {
    Speak() string
}
```

Любой тип с методом `Speak() string` автоматически реализует `Speaker`.

## 2. Реализация интерфейса

Реализация неявная — нет ключевого слова `implements`.

```go
type Dog struct {
    Name string
}

func (d Dog) Speak() string {
    return d.Name + " says Woof"
}

type Cat struct {
    Name string
}

func (c Cat) Speak() string {
    return c.Name + " says Meow"
}
```

Оба типа, `Dog` и `Cat`, реализуют `Speaker`, потому что у них есть метод `Speak() string`.

## 3. Использование интерфейса

```go
func Announce(s Speaker) {
    fmt.Println(s.Speak())
}

Announce(Dog{Name: "Rex"}) // Rex says Woof
Announce(Cat{Name: "Tom"}) // Tom says Meow
```

Функция `Announce` ничего не знает о `Dog` и `Cat` — ей важен только интерфейс `Speaker`.

## 4. Slice интерфейсов

```go
speakers := []Speaker{
    Dog{Name: "Rex"},
    Cat{Name: "Tom"},
}

for _, s := range speakers {
    fmt.Println(s.Speak())
}
```

Подробнее о `slice` — в [[14.go-slice]].

## 5. Пустой интерфейс — any

`interface{}` (или `any` начиная с Go 1.18) — тип, который может хранить значение любого типа.

```go
var value any

value = 10
value = "hello"
value = true
```

Аналог `any` в TypeScript или `object` в более широком смысле.

## 6. Проверка типа — Type Assertion

```go
var value any = "hello"

str, ok := value.(string)

if ok {
    fmt.Println(str) // hello
}
```

Без `ok` при несовпадении типа произойдёт panic:

```go
str := value.(string) // panic, если value не string
```

## 7. switch по типу — Type Switch

```go
func describe(value any) {
    switch v := value.(type) {
    case int:
        fmt.Println("int:", v)
    case string:
        fmt.Println("string:", v)
    default:
        fmt.Println("unknown type")
    }
}

describe(10)      // int: 10
describe("hello") // string: hello
```

## 8. Композиция интерфейсов

Интерфейсы можно объединять в новый интерфейс:

```go
type Reader interface {
    Read() string
}

type Writer interface {
    Write(data string)
}

type ReadWriter interface {
    Reader
    Writer
}
```

Тип должен реализовать все методы обоих интерфейсов, чтобы удовлетворять `ReadWriter`.

## 9. Интерфейс как поле struct

```go
type Logger interface {
    Log(message string)
}

type Service struct {
    logger Logger
}

func (s Service) Run() {
    s.logger.Log("service started")
}
```

Это позволяет подменять реализацию (например, для тестов) — похоже на Dependency Injection.

Подробнее о `struct` — в [[16.go-struct]].

## 10. nil интерфейс

```go
var s Speaker

fmt.Println(s == nil) // true

s.Speak() // panic: nil pointer dereference
```

Вызов метода на `nil` интерфейсе без реализации приводит к panic.

## 11. Сравнение с JavaScript / TypeScript

| JavaScript / TypeScript     | Go                                  |
| ---------------------------- | ------------------------------------ |
| `interface Speaker { ... }`  | `type Speaker interface { ... }`    |
| `class Dog implements X`     | неявная реализация (duck typing)     |
| `any` / `unknown`            | `any` (`interface{}`)               |
| `typeof x === "string"`      | `v, ok := x.(string)`               |
| `switch (typeof x)`          | `switch v := x.(type)`              |
| `extends` нескольких интерфейсов | встраивание интерфейсов (`Reader + Writer`) |

## Главное

- `interface` описывает поведение (набор методов), а не данные.
- Реализация интерфейса неявная — Go использует структурную типизацию (duck typing).
- `any` (`interface{}`) может хранить значение любого типа.
- `v, ok := x.(Type)` — безопасная проверка/приведение типа.
- `switch v := x.(type)` — ветвление по конкретному типу.
- Интерфейсы можно комбинировать, встраивая один в другой.
- `nil`-интерфейс без реализации вызывает panic при вызове метода.
