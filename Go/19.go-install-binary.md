# 19. go install — запуск проекта как бинарника из любой папки

Скрипты, которые работают с файлами **текущей папки** (например `go-scripts`),
нельзя запускать через `go run` из другой папки.

## 1. Почему не go run

```
cd /tmp/cyr
go run ~/Documents/go/go-scripts
# go: go.mod file not found in current directory or any parent directory
```

- `go run <путь>` работает только внутри модуля — `/tmp/cyr` не модуль.
- `go run -C ~/Documents/go/go-scripts .` соберёт, но программа запустится в
  папке проекта, а не в `/tmp/cyr`: `-C` меняет текущую папку.

## 2. Собрать и запустить

```
cd ~/Documents/go/go-scripts && go install .
cd /tmp/cyr && go-scripts
```

- `go install .` кладёт бинарник в `~/go/bin`.
- Имя бинарника — последняя часть пути модуля из `go.mod`:
  `module github.com/seriiserii825/go-scripts` → `go-scripts`.
- `~/go/bin` должен быть в `PATH`. Проверить:
  `echo $PATH | tr ':' '\n' | grep go`.
- Программа запускается в той папке, где ты сейчас, — как раньше `main.py`.

## 3. После правок кода

`go install .` нужно повторять после каждого изменения — иначе запускается
старый бинарник.

Если в проекте есть `go.work`, `go install .` собирает с **локальной** версией
библиотек (например `../go-libs`), без тегов.

## 4. Где лежит и как удалить

```
which go-scripts        # ~/go/bin/go-scripts
rm ~/go/bin/go-scripts  # удалить
```

Папка задаётся через `GOBIN` (по умолчанию `$(go env GOPATH)/bin`, то есть
`~/go/bin`): `go env GOBIN GOPATH`.
