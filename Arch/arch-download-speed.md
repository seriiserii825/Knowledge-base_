# Медленная загрузка файла: виновата сеть или сервер

## Пример

Загрузка бэкапа `.wpress` (173 MB) с сайта клиента шла на 60 kB/s, ETA 46 минут.

## Диагностика

Сравнить общую скорость интернета со скоростью от конкретного сервера:

```bash
# общая скорость (Cloudflare, 25 MB)
curl -s -o /dev/null -w "%{speed_download} B/s\n" --max-time 15 "https://speed.cloudflare.com/__down?bytes=25000000"

# пинг до интернета и до сервера
ping -c 4 -q 1.1.1.1
ping -c 4 -q example.com

# скорость от нужного сервера (15 секунд)
curl -s -o /dev/null -w "%{speed_download} B/s, ip %{remote_ip}\n" --max-time 15 "https://example.com/file"
```

Результат в том случае: общая скорость ~2.3 MB/s, а от сервера ~115 kB/s на соединение. Значит, проблема не в моей сети. Сервер ограничивает скорость **на одно соединение**: второй параллельный запрос получил скорость не хуже первого.

## Решение: aria2, загрузка в несколько потоков

Сначала проверить, что сервер отдаёт файл по частям (нужен `accept-ranges: bytes`):

```bash
curl -sI "https://example.com/file" | grep -iE "accept-ranges|content-length"
```

Поставить и качать в 16 потоков:

```bash
sudo pacman -S aria2
aria2c -x 16 -s 16 "https://example.com/file"
```

- `-x 16`: максимум соединений к одному серверу (16 — это предел).
- `-s 16`: на сколько частей делить файл.

Если ограничение действительно на соединение, скорость растёт примерно пропорционально числу потоков. Прерванную загрузку aria2 докачивает: та же команда в той же папке продолжит с места остановки (рядом лежит файл `.aria2`).

Если есть SSH или панель хостинга, можно забрать файл через `scp`/`rsync` или скачать прямо из панели.
