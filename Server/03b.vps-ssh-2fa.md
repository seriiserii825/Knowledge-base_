# 03b. 2FA для SSH: ключ + код из приложения

После настройки вход = **SSH-ключ** + **6-значный код** (TOTP) из приложения на телефоне. Даже если кто-то добавит свой
ключ или украдёт твой — без кода не зайдёт.

Перед этим: `03.vps-disable-root.md` и `03a.vps-ssh-authorized-keys-root.md`.

Приложение для кодов: Aegis (Android), 2FAS, Google Authenticator, Bitwarden/1Password — любое с TOTP.

> ⚠️ Держите открытой одну SSH-сессию до конца проверки. Если потеряли доступ — веб-консоль провайдера (OVH: KVM). Через
> KVM-консоль 2FA не спрашивается (это локальный вход, не SSH).

## Шаг 1. Проверить время на сервере

TOTP-коды зависят от времени. Если часы сервера ушли — коды не подойдут.

```bash
timedatectl
# System clock synchronized: yes
# NTP service: active
```

Если `no`:

```bash
sudo timedatectl set-ntp true
```

## Шаг 2. Установить модуль

```bash
sudo apt install -y libpam-google-authenticator
```

## Шаг 3. Создать секрет для пользователя

Под пользователем `node`:

```bash
google-authenticator
```

Ответы:

| Вопрос                                                                   | Ответ |
| ------------------------------------------------------------------------ | ----- |
| Do you want authentication tokens to be time-based?                      | `y`   |
| (показывает QR-код) — отсканировать приложением, ввести код для проверки |       |
| Do you want me to update your ".google_authenticator" file?              | `y`   |
| Disallow multiple uses of the same token?                                | `y`   |
| Increase the time window (to ~4 min)?                                    | `n`   |
| Enable rate-limiting?                                                    | `y`   |

**Сохраните emergency scratch codes** (5 одноразовых кодов) — в менеджер паролей. Это вход, если потеряете телефон.

## Шаг 4. Перенести секрет под root

По той же причине, что и `03a`: файл `~/.google_authenticator` принадлежит `node`, и взломанный процесс от `node` может
подменить его своим секретом. Переносим в каталог root:

```bash
sudo mkdir -p /etc/ssh/2fa
sudo chmod 700 /etc/ssh/2fa
sudo mv /home/node/.google_authenticator /etc/ssh/2fa/node
sudo chown root:root /etc/ssh/2fa/node
sudo chmod 600 /etc/ssh/2fa/node
```

## Шаг 5. Настроить PAM

```bash
sudo vim /etc/pam.d/sshd
```

1. Закомментировать строку с паролем (иначе после ключа будет спрашивать ещё и пароль):

   ```text
   # @include common-auth
   ```

2. Добавить в **начало** файла:

   ```text
   auth required pam_google_authenticator.so secret=/etc/ssh/2fa/${USER} user=root
   ```

   - `secret=` — где лежит секрет (`${USER}` → имя пользователя);
   - `user=root` — читать файл от root (он принадлежит root).

## Шаг 6. Настроить sshd

```bash
sudo vim /etc/ssh/sshd_config.d/00-hardening.conf
```

Было в `03`: `KbdInteractiveAuthentication no` — **поменять на `yes`** (через него приходит запрос кода). Итоговый файл:

```sshconfig
PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication yes
PubkeyAuthentication yes
UsePAM yes
AuthorizedKeysFile /etc/ssh/authorized_keys/%u
AuthenticationMethods publickey,keyboard-interactive
```

(+ `Port 2222`, если меняли порт в `04a`.)

`AuthenticationMethods publickey,keyboard-interactive` — нужно **оба**: сначала ключ, потом код.

```bash
sudo sshd -t
sudo sshd -T | grep -Ei 'authenticationmethods|kbdinteractive|passwordauth|usepam'
sudo systemctl restart ssh
```

## Шаг 7. Проверить (новый терминал)

```bash
ssh vps
# (Verification code: ← ввести код из приложения
```

Пароль спрашивать **не должен** — только код. Если спрашивает пароль — не закомментирован `@include common-auth` (шаг
5).

Проверить, что без ключа не пустит:

```bash
ssh -o PubkeyAuthentication=no node@<IP>   # ❌ Permission denied
```

Если не пускает с кодом — в открытой сессии:

```bash
sudo journalctl -u ssh -n 30 --no-pager
```

Частые причины: время на сервере (шаг 1), права/путь к секрету (шаг 4), опечатка в `/etc/pam.d/sshd`.

## Исключение для автоматического деплоя (если нужно)

CI (GitHub Actions и т.п.) не может ввести код. Для него — отдельный пользователь, только ключ, без sudo. В конец
`00-hardening.conf`:

```sshconfig
Match User deploy
    AuthenticationMethods publickey
```

## Если потеряли телефон

- Войти с одним из **emergency scratch codes** вместо кода (каждый одноразовый).
- Или через веб-консоль провайдера (KVM) → заново `google-authenticator` под `node` → шаг 4.

## Заметки

- `sudo` по-прежнему спрашивает обычный пароль `node` — 2FA только для SSH.
- Новый телефон: тот же секрет можно перенести экспортом из приложения, либо сгенерировать новый (шаги 3–4).
- Частый ввод кода надоедает → на своём компьютере держать одно соединение и переиспользовать его. В `~/.ssh/config` для
  `Host vps`:

  ```sshconfig
  ControlMaster auto
  ControlPath ~/.ssh/cm-%r@%h:%p
  ControlPersist 4h
  ```

  Код спросит только при первом подключении, следующие `ssh vps` / `scp` в течение 4 часов пойдут по уже открытому
  каналу.
