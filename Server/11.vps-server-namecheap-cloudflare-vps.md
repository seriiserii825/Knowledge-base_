# Домен из Namecheap → DNS в Cloudflare → VPS

Схема: домен куплен в **Namecheap** (регистратор), DNS обслуживает **Cloudflare**, записи указывают на IP VPS.

## 0. Узнайте IP сервера

```bash
dig +short vps-xxxxxxxx.vps.ovh.net        # IPv4
dig +short AAAA vps-xxxxxxxx.vps.ovh.net   # IPv6 (если есть)
```

Или на самом сервере:

```bash
curl -4 ifconfig.me   # IPv4
ip -6 addr            # IPv6: нужен глобальный адрес (не fe80::)
```

Дальше `<IP_VPS>` и `<IPv6_VPS>` — эти адреса.

## 1. Добавьте домен в Cloudflare

Панель: <https://dash.cloudflare.com>

- Нажмите "Onboard a domain" (раньше — "Add a Site")
- Введите ваш домен
- Выберите бесплатный план (Free)
- Cloudflare просканирует существующие DNS-записи — удалите старые/ненужные
- В конце Cloudflare покажет **2 nameserver'а** вида `xxx.ns.cloudflare.com` — скопируйте

## 2. Пропишите nameservers Cloudflare в Namecheap

1. Войдите в Namecheap → Account → Dashboard → **Domain List** (<https://ap.www.namecheap.com/domains/list/>).
2. Нажмите "Manage" рядом с доменом.
3. Вкладка **Domain** (не "Advanced DNS"!) → блок **Nameservers**.
4. Выберите "Custom DNS" и введите оба nameserver'а Cloudflare.
5. Нажмите зелёную галочку для сохранения.

После переключения вкладка "Advanced DNS" в Namecheap больше не используется — все записи теперь в Cloudflare.

Ожидание: от нескольких минут до 24 часов. Когда статус домена в Cloudflare станет **Active** — придёт письмо.

Проверка из терминала:

```bash
nslookup -type=ns seriiburduja.org
# или
dig +short NS seriiburduja.org
```

## 3. Добавьте DNS-записи в Cloudflare

DNS → Records → Add record. TTL везде Auto.

| Type | Name      | Content    | Proxy status    | Зачем                    |
| ---- | --------- | ---------- | --------------- | ------------------------ |
| A    | `@`       | `<IP_VPS>` | 🟠 Proxied      | основной домен (фронт)   |
| A    | `www`     | `<IP_VPS>` | 🟠 Proxied      | www                      |
| A    | `api`     | `<IP_VPS>` | 🟠 Proxied      | бэкенд (Nest, Socket.io) |
| A    | `livekit` | `<IP_VPS>` | ⚪ **DNS only** | LiveKit (звонки, WebRTC) |

### IPv6 (опционально)

Только если на сервере реально настроен IPv6 (`ip -6 addr` показывает глобальный адрес). Иначе часть клиентов будет ходить по IPv6 в никуда.

| Type | Name  | Content      | Proxy status |
| ---- | ----- | ------------ | ------------ |
| AAAA | `@`   | `<IPv6_VPS>` | 🟠 Proxied   |
| AAAA | `www` | `<IPv6_VPS>` | 🟠 Proxied   |

### Почему LiveKit — DNS only (серое облако)

Оранжевое облако (proxy) пропускает только HTTP(S)/WebSocket на стандартных портах. Медиа LiveKit идёт напрямую по **UDP 7882** и **TCP 7881** — через прокси Cloudflare это не пройдёт, звонки не соединятся. Поэтому `livekit` — только DNS, TLS для него делает Caddy/nginx на сервере.

То же правило для любого сервиса с нестандартными портами/UDP (SSH по домену, игровые серверы и т.п.) — серое облако.

## 4. SSL/TLS режим в Cloudflare

SSL/TLS → Overview → **Full (strict)**.

- На сервере должен быть настоящий сертификат (Caddy получает сам, для nginx — certbot, см. `13.vps-server-ssl.md`).
- **Не "Flexible"**: при нём Cloudflare ходит к серверу по HTTP, сервер редиректит на HTTPS → бесконечный редирект (`ERR_TOO_MANY_REDIRECTS`).

## 5. Проверка

```bash
dig +short seriiburduja.org           # proxied → IP Cloudflare (104.x / 172.x), это нормально
dig +short livekit.seriiburduja.org   # DNS only → должен быть IP VPS
```

`ping` на проксированном домене тоже покажет IP Cloudflare, а не сервера — это нормально.
