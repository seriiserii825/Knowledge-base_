# 05. Docker и Docker Compose

Установка из официального репозитория Docker (не `docker.io` из Ubuntu — там старая версия и нет `docker compose` v2).

Источник: <https://docs.docker.com/engine/install/ubuntu/>

## Шаг 1. Удалить конфликтующие пакеты (если есть)

На чистом сервере ничего не найдёт — это нормально.

```bash
for pkg in docker.io docker-doc docker-compose docker-compose-v2 podman-docker containerd runc; do
  sudo apt remove -y $pkg 2>/dev/null
done
```

## Шаг 2. Зависимости

```bash
sudo apt update
sudo apt install -y ca-certificates curl
```

## Шаг 3. GPG-ключ Docker

```bash
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
```

## Шаг 4. Репозиторий Docker

```bash
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
```

> Если `apt update` ругается на репозиторий Docker (`does not have a Release file`) — для этой версии Ubuntu Docker ещё не выпустил пакеты (бывает первые месяцы после релиза новой Ubuntu). Временно подставить кодовое имя предыдущей LTS (`noble` для 24.04) вместо `$(...)` в команде выше.

## Шаг 5. Установить Docker

```bash
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

## Шаг 6. Проверить

```bash
sudo docker --version
sudo docker compose version
sudo docker run --rm hello-world
```

## Шаг 7. Автозапуск

Обычно уже включён после установки, но проверить:

```bash
sudo systemctl enable --now docker
systemctl is-enabled docker   # → enabled
```

## Шаг 8. Docker без sudo

```bash
sudo usermod -aG docker node
```

Группа применится только в новой сессии — выйти и зайти:

```bash
exit
ssh vps    # алиас из 02, или ssh -p <PORT> node@<IP>
```

Проверить:

```bash
groups        # в списке есть docker
docker ps     # без sudo, без ошибки permission denied
```

> Группа `docker` = фактически root-доступ. Добавлять туда только своего пользователя.

## ⚠️ Docker обходит ufw

Порты, опубликованные в compose как `ports: - "5432:5432"`, Docker открывает **в обход ufw** — правила ufw на них не действуют, порт будет доступен из интернета.

Поэтому для всего, что не должно торчать наружу (БД, adminer, внутренние API), публиковать только на localhost:

```yaml
ports:
  - '127.0.0.1:5432:5432'
```

Наружу (`"80:80"`, `"443:443"`) — только reverse proxy (Caddy/nginx) и то, что действительно должно быть публичным (например, UDP-порты LiveKit).

Проверить, что реально слушается снаружи:

```bash
sudo ss -tlnup | grep -v 127.0.0.1
```

## Шаг 9. Ограничить размер логов (рекомендуется)

По умолчанию логи контейнеров растут бесконечно и могут забить диск.

```bash
sudo vim /etc/docker/daemon.json
```

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

```bash
sudo systemctl restart docker
```

Применяется к **новым** контейнерам (существующие — пересоздать: `docker compose up -d --force-recreate`).
