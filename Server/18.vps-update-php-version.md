# Как менять версию PHP для отдельного сайта в Hestia

Команды ниже выполняются от root. Перед изменением проверьте, какие PHP-шаблоны доступны:

```bash
/usr/local/hestia/bin/v-list-web-templates-backend
```

## Через терминал

Например, переключить ttcarservice-zerobranco.it с PHP 8.3 на PHP 8.4:

```bash
/usr/local/hestia/bin/v-change-web-domain-backend-tpl \
host ttcarservice-zerobranco.it PHP-8_4
```

Для сайта другого пользователя меняется первый аргумент:

```bash
/usr/local/hestia/bin/v-change-web-domain-backend-tpl \
webmaster plants.ethan-group.it PHP-8_4
```

Проверить назначенный шаблон:

```bash
/usr/local/hestia/bin/v-list-web-domain host ttcarservice-zerobranco.it json |
jq -r '.[].BACKEND'
```

Ожидаемый результат — PHP-8_4. Затем откройте сайт и проверьте, что он работает.

## Через панель

Web → нужный домен → Edit → Backend Template → PHP-8_4 → Save.

## Как вернуть прежнюю версию

Укажите прежний шаблон той же командой. Например, вернуть сайту PHP 8.3:

```bash
/usr/local/hestia/bin/v-change-web-domain-backend-tpl \
host ttcarservice-zerobranco.it PHP-8_3
```

Меняйте сайты по одному и проверяйте каждый после переключения. Для сайтов на PHP 7.4 переход на 8.4 требует особого
внимания к совместимости кода и плагинов.

## Смена версии и обновление пакета — разные действия

Команда Hestia выше переключает отдельный сайт между установленными ветками PHP, например с 8.3 на 8.4.

Обновление 8.4.18 до следующей 8.4.x выполняется через обновление пакетов PHP на сервере. Оно затронет все сайты,
использующие PHP 8.4.

## update php version

Да, установленные версии PHP нужно срочно обновить. Речь о двух критических уязвимостях PHP, а не о подтверждённом
взломе вашего сервера. Исправленные версии: 8.4.27 и 8.3.36. У вас сейчас 8.4.18 и 8.3.30, то есть обе ветки требуют
обновления. Официальное уведомление PHP, объявление релиза 8.4.27.

Обновлять каждый сайт отдельно не нужно. Обновление пакета php8.4-fpm затронет все сайты на 8.4; аналогично для 8.3.
Сначала проверьте, какие версии доступны из ваших репозиториев:

```bash
apt update
apt-cache policy php8.4-fpm php8.3-fpm php7.4-fpm
```

Если доступны исправленные пакеты, обновите сервер:

```bash
apt upgrade
systemctl restart php8.4-fpm php8.3-fpm php7.4-fpm
systemctl is-active php8.4-fpm php8.3-fpm php7.4-fpm

dpkg-query -W -f='${Package} ${Version}\n' \
    php8.4-fpm php8.3-fpm php7.4-fpm
```

Или только эти пакеты

```bash
apt install --only-upgrade \
    php8.4-fpm php8.4-cli \
    php8.3-fpm php8.3-cli \
    php7.4-fpm php7.4-cli
```

и проверить

```bash
dpkg-query -W -f='${Package} ${Version}\n' \
    php8.4-fpm php8.3-fpm php7.4-fpm
```

APT также предложит необходимые зависимости PHP. Просмотрите список пакетов перед подтверждением.

Затем проверьте:

```bash
php-fpm8.4 -v | head -n 1
php-fpm8.3 -v | head -n 1
./check-php-version.sh
```

Три сайта на PHP 7.4 требуют отдельного внимания: эта ветка давно не поддерживается проектом PHP. Их нужно перенести на
поддерживаемую ветку после проверки совместимости; если поставщик пакетов заявляет об отдельном исправлении для 7.4,
проверьте именно его номер пакета и уведомление о безопасности. Поддерживаемые версии PHP, рекомендация Ubuntu по
обновлению пакетов.

Если после apt update в apt-cache policy кандидат для 8.3 или 8.4 всё ещё старый, не считайте сервер исправленным.
Пришлите вывод apt-cache policy php8.4-fpm php8.3-fpm php7.4-fpm — по нему можно определить следующий шаг для ваших
репозиториев.
