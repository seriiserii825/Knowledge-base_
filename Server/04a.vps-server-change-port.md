# 04. Файрвол (ufw) и смена порта SSH

Цель: включить файрвол и (по желанию) перенести SSH с 22 на другой порт — меньше мусора от ботов в логах.

Смена порта — не защита сама по себе (защищает отключённый пароль из `03`), но уменьшает шум. Можно пропустить и
оставить 22.

Ниже порт для примера — `2222`.

> ⚠️ Всё время держите открытой одну SSH-сессию. Новую проверяйте в **другом** терминале. Если потеряли доступ —
> веб-консоль провайдера (OVH: KVM, Hetzner: Console).

## Шаг 1. Открыть порты в ufw (до смены порта!)

```bash
sudo ufw allow 22/tcp      # текущий SSH — пока не убирать
sudo ufw allow 2222/tcp    # новый SSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```

Включить файрвол:

```bash
sudo ufw enable            # на вопрос — y
sudo ufw status verbose
```

> Порты приложений (например LiveKit `7881/tcp`, `7882/udp`) — добавить так же, когда понадобятся.

## Шаг 2. Указать новый порт

```bash
sudo vim /etc/ssh/sshd_config.d/00-hardening.conf
```

Добавить строку:

```sshconfig
Port 2222
```

Проверить синтаксис:

```bash
sudo sshd -t
```

## Шаг 3. Применить

На Ubuntu 22.10+ SSH запускается через **socket activation** (`ssh.socket`): порт слушает systemd, а не sshd. Поэтому
после смены `Port` нужен `daemon-reload` — он пересоберёт сокет из конфига:

```bash
sudo systemctl daemon-reload
sudo systemctl restart ssh.socket
sudo systemctl restart ssh
```

Проверить, какой порт слушается:

```bash
sudo ss -tlnp | grep -E ':22|:2222'
```

Должен быть `2222`.

<details>
<summary>Если всё ещё слушается 22 — отключить socket activation</summary>

```bash
sudo systemctl disable --now ssh.socket
sudo systemctl enable --now ssh.service
sudo systemctl restart ssh
sudo ss -tlnp | grep ssh
```

</details>

## Шаг 4. Проверить вход по новому порту (новый терминал)

```bash
ssh -p 2222 node@<IP>
```

Если используете алиас из `02` — поменять в `~/.ssh/config` на своём компьютере:

```sshconfig
Host vps
    ...
    Port 2222
```

и проверить:

```bash
ssh vps
```

## Шаг 5. Закрыть старый порт

Только после того, как шаг 4 сработал:

```bash
sudo ufw delete allow 22/tcp
sudo ufw status
```

## Шаг 6. Файрвол у провайдера (если включён)

Если в панели провайдера включён сетевой файрвол (OVH: Network → Edge Network Firewall; Hetzner: Firewalls) — там тоже
открыть `2222/tcp`, иначе соединение будет висеть (timeout).
