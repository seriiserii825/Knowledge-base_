# 02. SSH-ключи: вход на сервер и доступ к GitHub

Здесь два **разных** ключа — не путать:

| Ключ                 | Где создаётся                | Зачем                          |
| -------------------- | ---------------------------- | ------------------------------ |
| `id_ed25519_vps`     | на **твоём компьютере**      | заходить на сервер без пароля  |
| `id_ed25519_github`  | на **сервере**               | сервер делает `git clone/pull` |

Перед этим: `01.vps-server-new-user.md` (пользователь `node` создан).

---

## Часть A. Вход на сервер по ключу (на своём компьютере)

### Шаг 1. Создать ключ

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_vps -C "home-computer"
```

Passphrase — по желанию (Enter = без пароля).

> Если ключ уже есть (`ls ~/.ssh/`) — можно использовать его, новый не обязателен.

### Шаг 2. Скопировать ключ на сервер

```bash
ssh-copy-id -i ~/.ssh/id_ed25519_vps.pub node@<IP>
```

Попросит пароль пользователя `node` (из шага 3 в `01`).

Если `ssh-copy-id` нет / не работает — вручную:

```bash
cat ~/.ssh/id_ed25519_vps.pub
# на сервере под node:
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo "<содержимое .pub>" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

### Шаг 3. Проверить вход (в новом терминале)

```bash
ssh -i ~/.ssh/id_ed25519_vps node@<IP>
```

Пароль спрашивать не должен (кроме passphrase ключа, если задавал).

### Шаг 4. Короткий алиас в `~/.ssh/config`

Чтобы не писать `-i`, `-p` и IP каждый раз. На **своём компьютере**:

```bash
vim ~/.ssh/config
```

```sshconfig
Host vps
    HostName <IP>
    User node
    Port 22
    IdentityFile ~/.ssh/id_ed25519_vps
    IdentitiesOnly yes
```

Теперь:

```bash
ssh vps
```

После смены порта (`04a.vps-server-change-port.md`) — поменять только `Port` здесь.

### Шаг 5. Второй компьютер (например, рабочий)

На **втором** компьютере — свой ключ (один ключ на устройство, чтобы можно было отозвать отдельно):

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_vps_office -C "office-computer"
ssh-copy-id -i ~/.ssh/id_ed25519_vps_office.pub -p <PORT> node@<IP>
```

Если вход по паролю уже отключён (`03`) — `ssh-copy-id` не сработает. Тогда с первого компьютера добавить содержимое `id_ed25519_vps_office.pub` в `~/.ssh/authorized_keys` на сервере.

И такой же блок `Host vps` в `~/.ssh/config` на втором компьютере (с `IdentityFile ~/.ssh/id_ed25519_vps_office`).

## Часть B. Доступ сервера к GitHub (на сервере)

Нужно, чтобы на сервере работал `git clone git@github.com:...`.

### Шаг 6. Создать ключ на сервере

```bash
ssh vps
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_github -C "vps-server"
```

### Шаг 7. Добавить ключ в GitHub

```bash
cat ~/.ssh/id_ed25519_github.pub
```

Скопировать вывод → добавить в GitHub одним из способов:

- **Deploy key** (рекомендуется, доступ только к одному репо): репозиторий → Settings → Deploy keys → Add deploy key. Галочку "Allow write access" не ставить, если сервер только делает `pull`.
- **Ключ аккаунта** (доступ ко всем репо): GitHub → Settings → SSH and GPG keys → New SSH key.

### Шаг 8. SSH-конфиг на сервере

```bash
vim ~/.ssh/config
```

```sshconfig
Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github
    IdentitiesOnly yes
```

```bash
chmod 600 ~/.ssh/config
```

### Шаг 9. Проверить

```bash
ssh -T git@github.com
# Hi <user>/<repo>! You've successfully authenticated, but GitHub does not provide shell access.
```

На первый вопрос про fingerprint → `yes`.

---

## ssh-agent — нужен не всегда

`ssh-agent` нужен, только если у ключа есть **passphrase** и не хочется вводить её каждый раз. С `IdentityFile` в `~/.ssh/config` агент не обязателен.

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519_vps
ssh-add -l   # список загруженных ключей
```

Действует до закрытия терминала.
