# 02. SSH-ключи: вход на сервер и доступ к GitHub

Здесь два **разных** ключа — не путать:

| Ключ                | Где создаётся                         | Зачем                          |
| ------------------- | ------------------------------------- | ------------------------------ |
| `id_ed25519_vps`    | **дома**, приватный хранится в `pass` | заходить на сервер (дом+работа) |
| `id_ed25519_github` | на **сервере**                        | сервер делает `git clone/pull` |

Перед этим: `01.vps-server-new-user.md` (пользователь `node` создан).

---

## Часть A. Вход на сервер по ключу — один ключ на дом и работу

Схема: ключ создаётся дома → публичный на сервер → приватный в `pass` (зашифрован твоим GPG-ключом, синхронизируется через git) → на работе достаётся из `pass` в `~/.ssh`.

> Делать **до** `03` (там отключается вход по паролю) — `ssh-copy-id` использует пароль `node`.

### Шаг 1. Дома

```bash
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_vps -C "vps"   # private + public
ssh-copy-id -i ~/.ssh/id_ed25519_vps.pub node@<IP>        # public → сервер (спросит пароль node)
pass insert -m ssh/vps < ~/.ssh/id_ed25519_vps            # private → pass
pass git push
```

### Шаг 2. На работе (и на любой новой машине)

```bash
pass git pull
pass ssh/vps > ~/.ssh/id_ed25519_vps
chmod 600 ~/.ssh/id_ed25519_vps                           # без этого ssh откажется использовать ключ
```

### Шаг 3. `~/.ssh/config` на обеих машинах

Чтобы не писать `-i` и IP каждый раз:

```bash
vim ~/.ssh/config
```

```sshconfig
Host vps
    HostName <IP>
    User node
    Port 22
    IdentityFile ~/.ssh/id_ed25519_vps
    IdentitiesOnly yes
```

После смены порта (`04a.vps-server-change-port.md`) — поменять только `Port`.

### Шаг 4. Проверить (в новом терминале)

```bash
ssh vps
```

Пароль спрашивать не должен.

### Пояснения

- **Публичный ключ на работе не нужен** — для входа SSH использует только приватный. Если понадобится: `ssh-keygen -y -f ~/.ssh/id_ed25519_vps`.
- **import не нужен** — SSH-ключ это просто файл (import бывает только у GPG-ключей).
- **В git безопасно**: без твоего GPG-ключа файл не расшифровать.
- **Passphrase на SSH-ключ** — по желанию. В pass ключ защищён GPG, но на диске после `pass ssh/vps > ...` лежит открытым. Добавить позже: `ssh-keygen -p -f ~/.ssh/id_ed25519_vps`.
- **Добавить ключ после `03`/`03a`** (пароль отключён, ключи под root) — `ssh-copy-id` уже не сработает, на сервере:

  ```bash
  echo "<содержимое .pub>" | sudo tee -a /etc/ssh/authorized_keys/node
  ```

## Часть B. Доступ сервера к GitHub (на сервере)

Нужно, чтобы на сервере работал `git clone git@github.com:...`.

### Шаг 5. Создать ключ на сервере

```bash
ssh vps
ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519_github -C "vps-server"
```

### Шаг 6. Добавить ключ в GitHub

```bash
cat ~/.ssh/id_ed25519_github.pub
```

Скопировать вывод → добавить в GitHub одним из способов:

- **Deploy key** (рекомендуется, доступ только к одному репо): репозиторий → Settings → Deploy keys → Add deploy key. Галочку "Allow write access" не ставить, если сервер только делает `pull`.
- **Ключ аккаунта** (доступ ко всем репо): GitHub → Settings → SSH and GPG keys → New SSH key.

### Шаг 7. SSH-конфиг на сервере

```bash
vim ~/.ssh/config
```

```sshconfig
Host github.com
    HostName github.com
    User git
    IdentityFile ~/.ssh/id_ed25519_github
    IdentitiesOnly yes
```

```bash
chmod 600 ~/.ssh/config
```

### Шаг 8. Проверить

```bash
ssh -T git@github.com
# Hi <user>/<repo>! You've successfully authenticated, but GitHub does not provide shell access.
```

На первый вопрос про fingerprint → `yes`.

## ssh-agent — нужен не всегда

`ssh-agent` нужен, только если у ключа есть **passphrase** и не хочется вводить её каждый раз. С `IdentityFile` в `~/.ssh/config` агент не обязателен.

```bash
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519_vps
ssh-add -l   # список загруженных ключей
```

Действует до закрытия терминала.
