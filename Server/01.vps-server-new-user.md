# 01. Первый вход и новый пользователь

Цель: работать на сервере не под `root`/`ubuntu`, а под своим пользователем (`node`) с правами `sudo`.

Дальше: `02.vps-server-ssh-keys.md` (вход по ключу) → `03.vps-disable-root.md` (закрыть root и пароли).

## Шаг 1. Первый вход

Данные — из письма провайдера (IP, логин, пароль).

| Провайдер       | Логин по умолчанию | sudo     |
| --------------- | ------------------ | -------- |
| OVH VPS         | `ubuntu`           | есть     |
| Hetzner, другие | `root`             | не нужен |

```bash
ssh ubuntu@<IP>   # OVH
ssh root@<IP>     # Hetzner и т.п.
```

На вопрос `Are you sure you want to continue connecting` → `yes`.

## Шаг 2. Обновить систему

```bash
sudo apt update && sudo apt upgrade -y
```

Если после обновления просит перезагрузку (`/var/run/reboot-required` существует):

```bash
sudo reboot
```

Подождать ~1 минуту и зайти снова (шаг 1).

## Шаг 3. Создать пользователя

```bash
sudo adduser node
```

Задать пароль (он нужен для `sudo`), остальные поля — Enter.

## Шаг 4. Дать права sudo

```bash
sudo usermod -aG sudo node
groups node   # в списке должно быть: sudo
```

## Шаг 5. Проверить

```bash
su - node
sudo whoami   # → root
exit          # вернуться к прежнему пользователю
```

Если вывод `root` — всё ок.

### Какой пароль спрашивают

В обоих случаях — **пароль `node`** (из шага 3).

- `su - node` спрашивает пароль того, **в кого переключаешься** → `node`. Если `su` запускать из-под root — пароль не спросит.
- `sudo ...` спрашивает пароль того, **кто запускает** sudo → после `su - node` это снова `node`.

Отдельного «пароля от sudo» нет: `sudo` всегда спрашивает пароль текущего пользователя, пароль root не нужен.

Для сравнения: в шагах 2–4 `sudo` запускает `ubuntu`. На OVH для него обычно настроен `NOPASSWD` — пароль не спросит; если спросит — пароль `ubuntu` из письма OVH.

## Шаг 6. Не закрывайте эту сессию

Дальше — `02.vps-server-ssh-keys.md`: закинуть SSH-ключ для `node` и проверить вход **в новом терминале**. Текущую
сессию держите открытой, пока вход по ключу не заработает.

## Заметка: UID пользователя и Docker

У OVH пользователь `ubuntu` уже занимает UID 1000, поэтому `node` получит **1001** (проверить: `id node`).

Это важно, только если в Docker монтируется код с хоста и внутри контейнера работает пользователь с UID 1000 (например,
`USER node` в образах `node:*`): файлы, созданные контейнером, будут принадлежать `ubuntu`, а не `node`. Для
prod-образа, где код копируется внутрь (`COPY`), это не важно.
